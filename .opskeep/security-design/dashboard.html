Ghana-based online store for washroom and cleaning products, serving households and businesses with online checkout, and institutions (banks, schools, government and private companies) through quote requests, quote threads and repeat orders

Why this tier

  • Online payments (mobile money and cards) are in scope, although the first build uses mock data and payment-provider test mode only
  • Customer and institutional personal data, delivery addresses, order and quote history, and message threads
  • File uploads (requirements sheets) from unauthenticated or lightly verified users
  • Privileged staff admin console that changes prices, catalogue, quotes and orders
  • Institutional buyers include government bodies and banks, who may treat procurement details as confidential
  • Ghana Data Protection Act, 2012 (Act 843) applies to personal data handling; legal position to be confirmed by the owner
  • Stack is plain PHP with no framework (DEC-011), Tailwind CSS and MySQL (DEC-001), on Namecheap cPanel hosting with the domain at Namecheap (DEC-012). Shared hosting limits isolation, secret handling, logging and deploy identity, and having no framework means protections a framework would supply must be built and tested by hand, so compensating controls are required
  • The payment provider is Paystack (DEC-002). Live use needs a verified Paystack business account owned by Belis Bell and passing GATE-006; the first build uses Paystack test keys only
Approval suspended. The last approved version was 0.3.0. Version 0.4.0 changes authentication (CHG-001), so the development lock is back on until the owner approves it. See section 12.

05AI and agent tools

NOT APPLICABLE to the product. The store has no AI features, no model calls and no agent tools in v1. Adding an AI assistant, chatbot or automated quote drafting is a material change and reopens this baseline.

Development agents are in scope. Coding agents (ID-009) get scoped repository and non-production access only, never production credentials, live payment keys or customer data, and they cannot merge, approve baseline changes or deploy (CTL-AGT-001, GATE-003). 09Supply chain, provenance and SBOM

  • Source and CI: repository (CMP-008) with protected branches, human review, secret scanning and dependency scanning on every pull request (GATE-002, GATE-003).
  • Dependencies: Composer and npm lockfiles, pinned versions, minimal packages, composer audit and npm audit in CI; generated code reviewed like any other (CTL-SC-001). Tailwind is compiled at build time, never loaded from a CDN in production.
  • Provenance and SBOM: build produces an SBOM and provenance attestation; only that artifact deploys (GATE-004, CTL-DEP-001).
  • Third-party runtime code: strict CSP, subresource integrity, short approved list; none on checkout or account pages without owner approval (CTL-SC-002).
  • Third-party services: payment provider, email and SMS, edge and hosting. Each needs an owner, scoped credentials and an exit plan. Payments use Paystack (DEC-002) and hosting is Namecheap cPanel (DEC-012).
  • Status: inventory is design-level only. No dependency list, SBOM or scan exists yet because nothing is built.
